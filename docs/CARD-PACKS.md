# 卡包与 JSON 格式（v1.0.0）

首页工具栏显示当前卡包，点击名称直接进入管理页选择卡包。仅内置连通性演示（6 张自编卡）；首次默认连通性演示，之后恢复上次选择。Tab 只展示当前包中存在的卡组织，全部指当前包内全部卡片，取消来源分类“自定义”。

管理卡包使用独立页面，分为内置卡包与我的卡包，显示名称、数量、两行说明和当前使用状态。点击整张卡包即可使用并返回首页，当前包保留“当前使用”标签；右侧菜单独立响应，查看完整 JSON、导出、重命名或删除。右上角“＋”提供“新建卡包”和“导入文件”。新建填写名称、可选说明，自动生成 ID；创建后使用空包并返回首页，可直接新建卡片。导入沿用预览确认流程，成功后返回首页。普通返回也刷新首页，切包与管理均不会启动模拟。

## 导入与管理

- JSON 导入先选择新建或更新某个用户包，再预览名称、卡片和整包变更数量。确认前不写入。
- 更新是整包替换：文件中缺失的旧卡将移除。内置包和自建卡片不可整包替换。
- 新建遇到相同 pack.id 时生成新的内部 ID，不覆盖原包；同 ID 更新必须明确确认。
- 导入成功自动切换到目标包。新建、复制默认归入当前用户卡包；当前为内置包时归入自建卡片。编辑默认保留原归属，编辑页可选择任意用户包；跨包移动只在保存时一次提交，目标编号冲突会拒绝且保留原卡。
- 卡包菜单支持查看完整 JSON，包含 pack 信息和全部 cards；空包也可查看。卡片列表与详情菜单统一提供“查看 JSON”，内容与对应导出文件一致，只读并可长按选择复制。
- 管理支持整包导出，用户包重命名与删除；自建卡片可以重命名但不能删除。删除包保留日志。
- 单卡导出仍为独立卡片文件，导入时建立新包，不作为原完整包的更新标识。

## 新格式

使用 schemaVersion=2，顶层 pack 必须有 id、name；description 可选。cards 内的 APDU 字段保持不变。完整示例见 ../examples/card-pack.json。

卡包 ID 和卡片 ID 各允许 1–100 位字母、数字、下划线、点、连字符。卡片 ID 只需包内唯一；内部 key 为 pack.id:card.id，导航、日志和模拟会话使用这个组合。导出文件仍保存包内卡片 ID。

文件不能声明自身为内置或只读，这些权限仅由应用加载入口赋予。标准单卡对象、卡片数组和 schemaVersion=1 的独立卡片文件作为新包导入；缺少 pack 时取文件名并生成新 ID。未知版本拒绝。不解析 cardID/cardImg/cardType/AID/APDU 等旧字段。

## 本地存储

用户包写入 card-packs.json，原子保存。不迁移旧 cards.json，也不提供旧内置包选择的升级转换。读取失败显示内置包与错误日志，禁止覆盖用户包文件。

每包最多 200 张、单包 JSON 最大 2 MB；最多 100 个用户包、共 2000 张用户卡，累计持久化数据最大 20 MB。空用户包允许新建、持久化和导出，文件导入须至少一张卡。

升级不改变 NFC 模拟规则：打开详情才请求启动，退出或后台停止；切卡包只切换列表，不启动模拟。APDU 匹配与回复引擎没有改动。
