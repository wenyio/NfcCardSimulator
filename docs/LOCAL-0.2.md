# 本地功能 0.2.0

本轮只推进本地卡模拟；minSdk 26 / targetSdk 31 / compileSdk 36。

## 模块

- MainActivity：生命周期、导航和页面组合。
- ui/cards：卡片列表、卡片编辑、规则编辑、交易导入预览，分别独立。
- ui/debug、ui/logs：手动会话、回复 TLV、会话日志。
- core：卡片模型、十六进制、规则引擎、JSON 编解码。
- importer：不依赖 Android 的 T:/C: 解析。
- diagnostics：BER-TLV 和按步骤的字节差异。
- data：卡片原子保存、日志后台批量保存。
- nfc、hce：系统 AID 路由和射频 APDU 服务。
- io：SAF 文件导入导出与后台文件读取。

核心规则匹配、会话重建、日志保存、导入配对及提交校验有中文注释。

## 使用

“新建卡片”可编辑名称、组织、AID、默认回复、按步骤开关；逐条添加/编辑 APDU，支持移除和上下移动。内置卡可以复制后编辑，保存副本会生成独立 ID。取消编辑不改原脚本，保存后停止模拟，需要重新启动以注册路由。

“导入文件”按内容识别 JSON 或交易文本。JSON 保持原有更新规则。文本每次选择一笔交易，在预览中核对 AID 后导入，生成 EXACT + ordered=true 脚本，不合并重复命令。

T 表示终端发送的 C-APDU；C 表示卡返回的 R-APDU（含 SW1/SW2）。例如 T: 00A4040007A000000152301000，随后一行 C: 9000。

这是一种本工具约定的文本格式，不是 ICC/Galitt 通用标准。允许大小写、空白、纯十六进制续行、# 注释。空行不分组，使用单独一行 --- 分隔交易；再次 SELECT PPSE 也会开始新分组。若一次射频会话含重复 PPSE，应使用 JSON 编辑后合并步骤。无 PPSE 的多笔记录需要显式分隔。格式错误、方向缺失、缺少回复会展示行号并禁止导入该笔。每文件最多 2 MB、200 笔，每卡 1000 条规则。SELECT 无法提取业务 AID 时需手填。

示例：examples/discover-session.txt；examples/discover-error-scenarios.json 可导入 AID 6A82 / GPO 6A80 错误路径。模板自编，仅用于终端错误处理，不代表 Discover 认证场景已通过。

## 日志和调试

按步骤未匹配时显示当前规则的字节差异（从 1 计数），MASK 只报告受比较位的差异；不推进步骤。按内容模式不推断“最接近”规则。回复 TLV 处理 BER 定长和长长度编码，最后两字节单独显示 SW；数据损坏显示解析原因。

手动和 NFC 会话各有独立 ID。日志最近 600 条，总消息字符上限 100 万；单条超 16000 字符会标明截断。第一条记录约 300 ms 后异步原子保存，强行结束进程可能丢失尚未写入的短窗口记录。日志不参与脚本执行。清空后也会保存空记录。诊断日志导出含时间、会话及说明，不能直接当作 T:/C: 导入；需整理为上述格式。

## 待设备验证

需要支持 NFC HCE 的 Android 手机与 P19：检查默认支付、AID 注册、PPSE/AID 收发、断场重置、连续交易、锁屏行为和时延。卓易通返回 false 只证明系统未接受路由，不能据此确定具体厂商限制。当前错误消息附路由信息以便对照设备。

正常交易、联机/脱机结果、ODA/动态密文依赖有效测试数据和相应算法；固定回复模板不能保证这些场景成功。后续基于实际测试日志补充 Discover 场景。项目范围不包含网络联动。
