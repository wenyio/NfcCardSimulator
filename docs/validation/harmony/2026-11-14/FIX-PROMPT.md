## 修复范围与验收

1. **首页支持左右滑动切换分类（UI-08）**
   - 当前 Index.ets 只有横向分类按钮和单个纵向列表，列表区域横滑不能切换分类。参考 Android CardsPage.kt、SwipePages.kt 的分类分页行为。
   - 点击分类与横滑内容使用统一的选择状态，顶部分类随选中项保持可见；首尾不越界。顶部分类条横向滚动不能代替内容区域分页。
   - 处理横滑、纵向滚动、卡片点击和更多菜单的手势冲突，滑动不能误打开卡片。覆盖慢拖、快甩、中途取消、切换卡包、空卡包和多分类；保持返回列表时合理的选择与滚动状态。

2. **详情页指示线跟随内容滑动（UI-09）**
   - 当前内容可以横滑，但连续帧显示调试页已占大部分屏幕时，指示线仍停留详情，落定附近才切换。用户另反馈落定后仍有明显延迟，需用录屏或帧级工具复现并测量；现有低频截图不足以确定毫秒数。
   - 检查 CardDetailPage.ets 的 Tabs、activeTab、onChange 与 SDK 支持的动画／滚动事件，避免状态回写触发第二段动画、重复切换或主线程工作阻塞。不要未经验证直接认定 onChange 是根因。
   - 指示线应与内容位移协调跟随，落定后不再额外补动；点击页签、连续左右切换、反向和取消手势均正常。不能通过移除指示线或禁用滑动掩盖问题。切页不得重启 NFC／手动脚本会话或清空输入、规则展开。

3. **统一主题与控件可读性（UI-01、UI-02）**
   - 复核 EditorField 的 TextInput/TextArea、DebugPanel 的 Select/TextInput、详情 Tabs 及其他共用表单。历史真机截图中文字存在于 UI 树，但在白底上不可见；未选中页签也近乎白色。
   - 选择一致的主题策略，明确控件文字、提示、背景、选中和禁用状态的对比度，覆盖浅色及深色系统外观。验证下拉弹层、键盘弹出、十六进制长输入和多行文本；不能只修一处截图。

4. **编辑页标题去重（UI-03）**
   - 外层标题与 EditorField.fieldLabel 重复，涉及 AID、说明、未匹配回复。每字段保留一处主要标题，将单位／格式约束放在该处或必要辅助说明，不删掉新人需要的格式要求。

5. **系统栏与页面外观衔接（UI-04）**
   - 旧版顶部、底部是黑条，Android UiKit.systemBars 使用 #152538；复核当前表现后统一状态栏、导航／手势区颜色与图标明暗，按鸿蒙规范处理安全区、挖孔、键盘和弹层，达到整体衔接的视觉效果。
   - 参考 Android 的实际颜色和布局，不把全屏 API 当作唯一目标；不能让内容被系统栏遮挡。

6. **两个系统设置入口正确引导（UI-05、UI-06）**
   - 已分别实测：NFC 设置、默认支付设置都落到系统设置主页；NfcController.ets 两者共用 launchSettings(MainAbility)。
   - 查证当前 HarmonyOS SDK／设备公开支持的跳转方式，分别进入 NFC 和默认支付专页。不要臆造私有 ability、URI 或使用系统专属权限。若平台确实不允许直达，保留可用入口并向用户明确说明已确认的手动路径及限制，报告中如实标注降级。覆盖首页与详情中的入口及返回应用后的状态。

7. **同步应用图标（UI-07）**
   - 当前真机桌面上鸿蒙原生图标近乎空白，Android 是深蓝底、蓝白卡片及 NFC 波纹。复用 Android ic_launcher_foreground.xml 的既有图案和配色，制作符合鸿蒙规范的资源；不要重新设计品牌。
   - 核对 AppScope、entry 的 layered_image 和启动窗口资源引用，验证安装后的桌面图标及冷启动显示，确保安全区裁切正常。

8. **导入成功立即显示目标卡包（UI-10）**
   - Android 的 importPack 成功后 switchPack(saved.id)，首页完成回调 showList，管理页完成后 finish 并由首页刷新；应显示目标卡包列表，不自动打开卡片或启动模拟。
   - 鸿蒙已有 switchPack，不要误判为缺少赋值。检查其先 setEnabled → log → 同步 notifyChanged、后更新 activePackId 且末尾不再通知的顺序：监听者可能先读取旧卡包，Index 的 @State 快照随后未更新。管理页导入仅 pop，首页直接导入另有 refresh，必须分别复现。
   - 统一提交成功后的状态通知及导航返回刷新，使标题、卡片、分类和持久化状态一致。保留停止模拟、清除选卡的语义。覆盖首页／管理页导入、新建／更新包、重启恢复；取消及失败不切换。当前尚无本轮独立导入复现记录，不将源码推断当作真机结果。

9. **卡片列表长标题完整显示（UI-11）**
   - 用户报告名称变成省略号，本地 Index.ets 的 Text(card.name) 确有限制单行并 Ellipsis；Android CardsPage/UiKit.label 允许换行。参考 Android 调整列表名称布局与自适应行高，保留更多菜单空间及点击区域。
   - 先核对当前安装版本并复测。REPORT 中 harmony-title-live.jpeg 的首页长名称已经换行，不能据此宣称当前所有长标题均截断；harmony-title-current.png 与同名 JSON 页面不同步，该 PNG 仅是详情工具栏省略，不能作为列表证据。
   - 用长中文、长英文、无空格标识与大字体检查完整名称、换行、卡片高度及菜单。不要修改名称数据、缩小至难读字号或使用固定高度裁切。将列表名称、首页卡包标题及详情工具栏分开验证。

## 优先修复：默认付款列表中没有应用（HCE-02，P1）

用户卸载 Android 版后，鸿蒙版仍未出现在系统默认付款列表。已通过源码与真机 bm dump 确认 EntryAbility.metadata 为空，缺少 payment-aid。公开文档说明 HCE 应用声明 payment-aid 才会纳入支付服务列表。当前代码又要求 isDefaultService 为 true 才启动，形成用户无法完成前提的阻塞。

- 按当前 SDK 规范补齐 HCE ability 的 payment-aid metadata，核对 HOST_APDU_SERVICE 的 skill/action 匹配；优先解决被系统发现和选择的问题，保留默认支付检查。
- 查明有效 AID 的声明格式及静态发现入口与动态选卡路由的关系，可参考 Android PPSE 配置，但不要盲目登记所有卡组织 AID。不要使用仅系统应用可调用的 getPaymentServices 或新增不必要的系统权限。
- 保留数据升级安装后，先用 bm dump 确认 metadata 已进入安装包，再验证默认付款列表中出现鸿蒙应用、可选择、返回应用后检测就绪。不把声明修复或启动成功当作射频收发通过。
- 更新报告，将用户观察的列表现象、已确认的配置缺失、修复后的真机结果分别记录。当前证据路径为同目录 hce-installed-declaration-evidence.txt。

## HCE 策略限制：保留默认支付检查

HCE-01 是待验证事项，不属于本轮直接移除限制的修复项。当前 NfcController.start 在非默认支付状态下先拦截，尚未调用系统 HceService.start。SDK 文档和 OpenHarmony 实现支持前台优先，但缺少该华为真机非默认支付状态下的 PPSE／支付 AID 射频收发证据。按用户要求保留 Android 版默认支付检查；不要因为 start 接口可能成功，就宣称已验证真实卡模拟。说明这一点即可，不必为本轮 UI 修复改动 HCE 策略。
